# ADR-003: 不用 MPU6050 DMP，纯原始数据 + 互补滤波

## 状态

Accepted（2026-09-06）

## 背景

MPU6050 内部有 DMP（Digital Motion Processor）固件可硬件解算姿态（输出四元数或欧拉角），或选择读 6 轴原始数据由 MCU 自己融合。

## 决策

**不用 DMP。读 ax/ay/az/gx/gy/gz 原始数据，由 MCU 跑互补滤波算欧拉角（Roll/Pitch），Yaw 纯陀螺仪积分。**

```c
#define MPU6050_FILTER_ALPHA  0.98f   // 陀螺仪权重 98%

roll  = α × (roll  + gx × dt) + (1-α) × atan2(ay, az)
pitch = α × (pitch + gy × dt) + (1-α) × atan2(-ax, sqrt(ay²+az²))
yaw  += gz × dt                      // 纯积分，接受漂移
```

## 原因

1. **DMP 移植成本高**：InvenSense 官方 motion_driver 库跨 GCC 移植坑多（I2C burst 时序、DMP 固件加载、内存对齐）
2. **flash 占用**：DMP 移植约 30-40KB，本工程只需 16KB
3. **F103 无 FPU**：DMP 内部浮点运算消耗算力，原始数据 + 简单互补滤波更轻
4. **互补滤波对 Roll/Pitch 足够准**：α=0.98 是行业标准值，静止时误差 < 1°
5. **Yaw 不可救药**：DMP 也不行，因为没有磁力计；纯陀螺仪积分的漂移 ≈ ±1°/s
6. **代码可读性**：互补滤波 ~20 行，DMP 调用 200+ 行 wrapper

## 后果

- Yaw 数值会缓慢漂移（约 ±1°/s），UI 显示 "Yaw: live" 文字占位，**不显示数值**
- 互补滤波对振动敏感（陀螺仪权重高导致瞬时误差），但人体手势下可接受
- 真机测试中如发现 Roll/Pitch 抖动 > 2°，考虑降到 α=0.95（加速度计权重升到 5%）
- 未来加磁力计（如 HMC5883L）可获得绝对 yaw，需重审本决策

## 替代方案

- **A. DMP + InvenSense 库**：效果最好，移植成本最高（flash 30-40KB，1-2 天调试）
- **B. 卡尔曼滤波**：理论最优，工程实现复杂，参数难调
- **C. Mahony 互补滤波**：与本方案本质相同，更复杂的形式，收益不明显

## 风险

- α=0.98 在振动环境下可能不优（陀螺仪积分误差累积）
- 缓解：v0.2 可调 α 走配置文件；或加低通滤波陀螺仪原始值
