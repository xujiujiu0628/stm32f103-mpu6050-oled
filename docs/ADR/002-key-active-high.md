# ADR-002: PA0 按键高电平触发（与 button-toggle 极性相反）

## 状态

Accepted（2026-09-06）

## 背景

用户硬件上 PA0 连接的按键是**按下高电平**触发（按键导通 VCC），与 stm32f103-button-toggle 工程的 PA0 **按下低电平**相反。如果照搬 button-toggle 的 key.c，按键永远检测不到（永远处于"已按下"或"未按下"取决于内部上下拉配置）。

## 决策

**PA0 配置为内部下拉输入，按下时高电平，释放时低电平。**

```c
gpio.Mode = GPIO_MODE_INPUT;
gpio.Pull = GPIO_PULLDOWN;   // 关键：按下高电平 → 必须下拉
```

## 原因

1. **硬件特性**：用户的按键硬件是按下导通 VCC（高电平有效）
2. **GPIO 配置对应**：高电平触发 → 内部下拉 → 未按下时低电平（确定状态）
3. **不能复用 button-toggle 的 key.c**：button-toggle 是低电平触发 + 上拉，逻辑相反

## 后果

- key.c 完全重写，**不复用** stm32f103-button-toggle 的 key.c
- 上升沿触发 + 50ms 消抖
- 长按阈值 1000ms（与 button-toggle 保持一致，便于用户跨工程使用）
- 未来加第二个按键需要明确指定极性

## 检测方法

真机验证时如果按键按下无反应：
1. 万用表量 PA0 对地电压：未按下 ≈ 0V，按下 ≈ 3.3V
2. 测的相反 → 硬件是高电平还是低电平，**先看硬件再看代码**

## 替代方案

- **A. 改用 PC13 用户按键**（板上 LED 旁）：但占用 LED 显示
- **B. 改用其他引脚（PB1/PB2 等）**：无强需求，保持 PA0
- **C. 软件修正（按下低电平识别）**：违反硬件事实，不可接受
